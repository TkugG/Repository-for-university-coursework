🧩 Design Patterns ที่ใช้

Singleton — Database ป้องกัน PDO connection ถูกสร้างซ้ำซ้อน ทุก class เรียก Database::getInstance() แล้วได้ instance เดิม

Composition — Request สร้าง Logger ภายใน constructor เพื่อ inject dependency แทนการ inherit ตามหลัก Favor Composition over Inheritance

SRP (Single Responsibility) — แยก Logger ออกจาก Request ทำให้แต่ละ class มีหน้าที่เดียว

📌 Method ที่น่าสนใจ

Request::generateRequestNumber() — สร้างหมายเลขอัตโนมัติ รูปแบบ SCR-{ปี 2 หลัก}{เทอม}-{0001} เช่น SCR-671-0001

Student::isEligibleForSpecialCourse() — ตรวจสิทธิ์ก่อน submit: ปี 4+ หรือนักศึกษาภาคค่ำ/เสาร์อาทิตย์

Logger::resolveIp() — รองรับ Cloudflare, Proxy, Load Balancer โดยอ่าน header ตามลำดับ CF → X-Forwarded-For → REMOTE_ADDR

🔄 State Transitions — รายละเอียด

PENDING (status_id=1) — initial state REVIEWING (2) — เจ้าหน้าที่รับเรื่อง APPROVED (3) — อนุมัติ + approval_date REJECTED (4) — ไม่อนุมัติ + review_notes CANCELLED (5) — ยกเลิกโดยนักศึกษา

ทุกการเปลี่ยนสถานะผ่าน Request::updateStatus() ซึ่งใช้ Database Transaction และเรียก Logger::log() อัตโนมัติ เพื่อให้ audit trail สมบูรณ์แม้ transaction rollback

📡 การไหลของข้อมูล (Data Flow) ในการยื่นคำร้อง

ขั้นที่ 1 — Security Gate: verifyCsrfToken() ตรวจสอบ token ก่อน และ abort ทันทีถ้าไม่ผ่าน ป้องกัน CSRF attack

ขั้นที่ 2 — Validation: validateRequestForm() ตรวจ format ฝั่ง server (ไม่พึ่ง JS client เพียงอย่างเดียว)

ขั้นที่ 3 — Business Rules: ตรวจสิทธิ์นักศึกษาและตรวจวิชาซ้ำ — ถ้าไม่ผ่านจะ short-circuit คืน error ทันทีโดยไม่สร้างคำร้อง

ขั้นที่ 4 — Atomic Write: Request::create() ใช้ Transaction ครอบ INSERT + Logger.log ถ้า Logger ล้มเหลว ทั้ง transaction จะ rollback ทำให้ข้อมูลสมบูรณ์เสมอ
